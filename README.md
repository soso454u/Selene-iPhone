# SillyTavern Selene手机

Selene手机把手机聊天和酒馆正文放在同一个 RP 时间线。手机用单独的请求生成在线互动；要进入正文的手机事件，会附在下一条正常用户消息上。反方向只读取已发生的正文事件，不为已经写出的消息另调模型。

## 安装

推荐使用远程导入：在酒馆助手中新建 JavaScript 脚本，粘贴下面这一行，保存并启用。可设为全局脚本。

```js
import 'https://gcore.jsdelivr.net/gh/soso454u/Selene-iPhone@v0.1.2/dist/index.js';
```

以后发布新版本时，只需把 `@v0.1.2` 改为已发布的版本号，保存后重新启用脚本或刷新酒馆。版本号必须对应仓库真实存在的 Git 标签；只修改数字不会产生新版本。固定版本链接不会自动跳到最新版。这个写法无需给 `https:` 加反斜杠。

可以直接复制 [`dist/import.js`](dist/import.js) 的内容。远程入口与本地完整脚本采用相同的账本和设置，更新加载方式不清空已有数据；每次更新仍建议保留备份。同一时间只启用一个小手机入口。首次运行和重新加载远程版需要能访问 CDN。

如不使用远程导入，仍可按以下步骤粘贴完整脚本：

1. 在 SillyTavern 安装并启用 **酒馆助手（JS-Slash-Runner）**，打开其「脚本」管理界面。
2. 新建脚本，把 [`dist/Selene手机.js`](dist/Selene手机.js) 的**全部内容**粘贴进去，保存并启用。希望切换角色后继续使用时，将其设为全局脚本。无需安装本项目为第三方扩展，也无需导入世界书或修改酒馆源码。
3. 打开一个角色聊天或群聊，点悬浮手机图标或酒馆魔法棒工具栏中的「Selene手机」 → **设置**。选择酒馆当前连接（聊天补全或新版文本补全）或独立 OpenAI 兼容 API。独立模式填 Base URL（如 `https://your-provider.example/v1`）、模型名及所需密钥。点**测试连接**会发送一个不带 RP 的短请求，可能计费；获取模型列表不发生成请求。供应商不提供列表时手填模型。
4. 从**通讯录**进入会话。发送只保存玩家气泡，可以连续发多条文字、语音或附件；发完后点击右上角「···」旁的星形按钮，才统一请求角色回复。可在聊天详情的回复设置里预览上下文（不请求）。长按或右键消息可引用、选择是否纳入正文，或在交接前编辑、删除、重试最后一组角色回复。

输出 Token 默认 `0`，表示手机不额外设置输出上限；独立 API 不发送 `max_tokens`，由服务商的默认值与模型能力决定，并不等于模型可以无限生成。可以填写正整数，手机不再限制到 4000。Claude 原生接口需要明确上限时沿用酒馆当前连接的值；连接测试仍限 16 Token。首次升级会把旧版本保存的输出上限迁移为 `0`，之后用户设置的数值正常保留；上下文预算是另一项设置。

内部模块统一通过酒馆宿主窗口的模块加载器读取，复用宿主已初始化的模块，避免从脚本 iframe 导入另一套酒馆依赖而触发 `SlashCommandParser` 初始化错误。更新脚本后若旧模块错误仍驻留，请刷新整个酒馆页面再使用。

模型列表从服务端实际返回结果读取，兼容标准列表和酒馆转发包装；`{error:true}` 会显示转发失败，而不会被当作空列表或服务不支持列表。成功后提供模型下拉框，也保留手填 ID。独立 DeepSeek 连接需填写密钥；密钥框会区分「未设置」与「已保存」。密钥持久保存在当前酒馆账号的浏览器存储中，刷新或重新导入更新脚本后保留；留空保存会保留已有密钥，也可主动清除。不会借用酒馆主连接中的密钥。

「连接与模型」内可以给当前 API 方案命名，保存、选择即切换和删除方案；同名保存更新原方案。方案包含生成通路、地址、模型、温度、输出上限和流式接收配置，对应密钥单独保存，不进入方案数据或剧情。应用方案时恢复该方案的密钥；手动更换服务地址而未填新密钥时清空当前连接密钥。

「各平台 API」可以给朋友圈、小红书、抖音、微博、论坛和 X 分别选择保存的方案；每个平台可使用不同的地址、模型和密钥，默认跟随聊天连接。发布页选择「AI 生成」，可选发言人、主题要求以及一次生成 1 / 3 / 5 条动态（X 为 5 / 6 / 7 条，默认最多 7 条）。这是动态条数；每条动态是否配图、配几张由角色按性格、发布意图和内容自行决定（0–9 张），可纯文字、单图或多图，不默认只配一张，也不与手动生图张数绑定。无论选择多少条，都只发送一次生成请求；多条动态使用 `posts` 数组，各自保留标题、正文及媒体描述。完整接收后统一保存，格式错误、失败或取消时不补发请求。角色仍可根据剧情选择不发布。

各平台默认采用中等精简的内容与语气规则，避免重复手机预设中的人物约束。生成时只发送一份通用社交规则和当前平台规则：朋友圈侧重熟人近况与随手记录；小红书侧重有独立标题的生活图文、兴趣与经验；抖音使用简短发布文案，把镜头及场景放在媒体描述中；微博侧重公开观点、兴趣话题与有来源的互动；论坛要求主题标题、背景和具体问题或讨论内容；X 使用通常每条一两句的匿名小号、私人表达、审美与互动短帖，可附虚构的角色账号名。X 有发布动机时，在所选上限内生成 5–7 条，无发布动机仍可不发。配图数量由角色按内容决定，不固定只配一张。平台习惯不会覆盖人物性格，不自动捏造热搜、爆红或互动数据。发布面板会显示当前应用的风格提示。动态条数继续由发布面板选择（所选上限不变），本轮有动态时仍要求合计至少 15 条评论；不采用按平台减少评论的参考表。

各平台的 AI 动态可以来自现在、昨天、几天前、数月前，甚至一年前，不局限于当前时间点或最近几天。模型在每条 `payload.postedAt` 返回剧情发布时间，帖子按该时间显示并持久保存；评论可用自己的 `postedAt`。剧情日期未知时使用“3天前”等相对时间，不借用设备日期。补出历史帖子不会改变设置里的 RP 时间、推进正文时间，也不会把之后才知道的内容写入旧帖。发布要求里可以直接指定“一年前的旅行记录”等主题。聊天和通话的时间规则保持原样。

微博、抖音、小红书及论坛的详情评论区提供“AI 生成评论”，使用当前平台 API 单次补充模拟评论，保留原帖，去除重复评论；不会代替玩家发言，也不会失败后自动补发请求。新动态的输出示例明确包含评论，并兼容模型把评论写在主帖对象外层。社交列表按帖子分页，每帖已有互动单独读取，避免被最近 80 条记录的窗口截掉。

论坛使用标题与摘要列表，点开后展示主楼、配图和编号楼层，可切换“只看楼主”；微博使用博文、配图网格、转评赞和正文评论区；抖音使用竖屏内容卡、横向多图、侧边互动及评论抽屉。三者保留发布、按需生成、搜索或分类、收藏、分享、评论和帖子菜单；画面只有描述时显示可点击媒体卡，不伪造可播放视频。图片生成与评论输入面板保持在当前详情内，发送后能继续查看回复。

锁屏通知中心与通知页右上角提供圆形“×”，一键清除当前通知。清除状态按当前聊天保存在本机，刷新后保留；帖子、聊天及剧情记录不删除，新收到的通知仍会显示。

X 使用独立的短帖信息流：头像、昵称、账号与发布时间同行显示，正文后是媒体格与图标互动栏；回复默认收起，可展开查看。关注、同步范围和删除操作在帖子右上角菜单中。顶部可切换推荐/关注，底部提供主页、搜索、书签和个人帖子，右下角按钮发布动态，星形按钮打开角色生成面板；各项只使用手机已有记录，不连接真实 X 账号。

所有平台的评论输入框均支持点击外部区域、取消、Esc 或切换页面后收起。输入框内选表情、提及或正常输入不会触发外部关闭；取消输入不提交评论，也不调用模型。

「设置 → 各平台提示词」提供全平台通用规则与朋友圈、小红书、抖音、微博、论坛、X 六份独立文本。平台自定义文本替换对应内置风格，通用规则用于所有动态；每份可恢复内置文本，编辑停顿或离开输入框后自动保存。留空使用内置规则。升级时仅将与旧内置文本完全一致的默认提示词更新为新版，用户改写的提示词保留；保存后刷新及更新脚本继续保留，已绑定角色时按角色保存，并可通过更新绑定随角色卡分享。编辑平台提示词不会修改聊天预设或切换 API。

默认通用规则要求所有帖子和评论像真人在对应 App 打字、可读正文使用简体中文，不替玩家发言。匿名路人仅根据帖子公开内容互动，不加入通讯录；朋友圈保持合理熟人范围。若本轮有动态，提示模型合计生成至少 15 条多样评论，可在通用文本修改这个要求；单帖最多接收 40 条有效评论。单条或批量动态的 `payload.comments` 与主帖在同一次请求内生成并一起写入本地账本，昵称、回复引用和评论数量直接显示在各应用；不为补足数量自动追加请求。评论可按原规则回复、删除及同步，是否进入正文沿用所属动态设置。结构化输出协议和既有应用界面保留，粘贴的 HTML/CSS 不作为页面代码执行。

独立 OpenAI 兼容 API 默认使用流式接收；可在设置中关闭。SSE 心跳与推理字段不作为手机正文保存，界面显示已接收字符数，完整结构化回复成功结束后才写入账本。连接测试只验证短请求，不能保证正式剧情请求的耗时也满足网关限制；504/524 会明确提示网关超时。断流、取消或输出截断时不写入半条角色回复，也不会自动重试付费请求。流式传输可减轻长时间无数据的情况，但服务器反向代理缓冲或硬超时仍需在服务端调整。

研究基线：SillyTavern **1.19.1**，酒馆助手主分支 manifest **4.12.1**。使用了原生客户端事件及内部模块；旧版本、自定义分支或调换了生成事件顺序的扩展需要单独验证，不承诺兼容。旧版专用连接（例如 Kobold Classic/NovelAI 主连接）请使用可用的独立 OpenAI 兼容端点。

## 使用方法

设置页统一使用单层搜索栏、柔和底色的分组图标和一致的按钮、输入框样式。名称及工具栏入口统一为「Selene手机」。构建同时保留旧文件名兼容已有引用，两个脚本内容相同。

顶部状态栏与页面共用背景：自定义页面背景延伸至顶部和底部；音乐全屏播放页的封面色渐变覆盖整部手机，切歌后同步取色，避免顶部出现独立浅色条。

「设置 → 外观 → 从正文自动读取 RP 时间」默认开启，读取当前聊天有效正文中最近明确的时间栏、日期栏或时钟描述，支持 `2026-11-21 18:30`、`11月21日`、`晚上八点半` 等。选择「锁屏与状态栏时钟 → 剧情时间」后，状态栏、主屏与锁屏显示该时间，手机消息及生成上下文也使用同一剧情时间。正文更新、编辑、删除、Swipe 或切换聊天时重新读取；不写回手动时间，不使用消息发送时间或设备日期补全，也不按现实时间走时。仅识别到时刻时不沿用旧正文日期，仅有日期时钟面保留未知。代码、思考块、手机事件、用户指令、引述及明确的回忆/计划不作为当前时间；无明确结果时使用手动填写值，留空则保持未知。关闭自动读取可完全使用手动时间。

「设置 → 外观 → 壁纸」保留原有三款，另加入「精选壁纸 1–4」，按提供顺序使用四张在线图片（用户提供的 `.md.png` 地址），不把图片内置进脚本。选择后自动保存，主屏幕与锁屏会使用所选壁纸，并沿用遮罩和居中铺满效果；已有自定义壁纸不会在升级时改变。主动切换下拉选项会清空表单里的旧自定义地址，避免遮盖新选择；也可填写新地址或上传图片覆盖预设。修复旧遮罩拼接成 `#0004d` 等无效五位颜色导致整条背景失效的问题，改用有效的 `rgb(0 0 0 / 透明度)`，图片后保留内置背景作为加载回退。

「外观 → 我的壁纸」可将图片链接或本地图片取名保存，最多 30 张。上传图片最大 2 MiB，图片本体放在 IndexedDB，设置只保存小体积引用，避免多张上传图片挤满浏览器设置空间。保存后加入上方壁纸下拉列表，可直接切换、编辑名称或图片、移除；已有的自定义图片也可点「保存当前壁纸」取名加入。恢复内置壁纸保留收藏列表，恢复默认脚本也保留已存壁纸。

支持 `freeimage.host/i/...` 图片展示页：先转换为同站图床 `iili.io` 的候选直链并检查实际图片格式，成功后保存图片直链。例如截图中的 `https://freeimage.host/i/oK7tvF2` 对应 `https://iili.io/oK7tvF2.jpg`。原来已保存的这种链接也会在显示时解析；普通网页无法加载为图片时显示错误，新增或修改失败时保留原壁纸。只检查用户提供的图片，不调用模型。壁纸名称及本地图片跟随现有完整备份与云端恢复；绑定角色外观时嵌入图片，换设备后仍可使用。角色外观已绑定时，壁纸库沿用该角色的外观保存范围。

「设置 → 外观 → Selene 音乐灵动岛」默认开启。兼容播放器在实际同源 ROOT 提供 `window.__SELENE_MUSIC_PLAYER__`，实现版本 1 的 `getPlaybackState / play / pause / togglePlayback / previousTrack / nextTrack / seekTo`，并在 ROOT 派发 `selene-music-playback-state` 后，手机会自动联动。无播放器、旧接口、未加载实际曲目或只有静音保活时保留原摄像头。手机和播放器独立运行，本项目不包含播放器实现。

播放时顶部摄像头横向展开，显示真实封面和六根 CSS 音律柱；同源或内嵌封面可安全取色时随封面变色，其他封面使用低饱和默认色，不为取色发额外请求。点击打开黑色大圆角音乐卡片，较大的封面、右侧同色音律、两端时间与细进度条、圆润双三角切歌键和居中播放键按 iOS 比例排列；可切歌、暂停/继续、拖动进度。再次点击或点外部收起，长按通过已有 `setVisible(true, { expand: true })` 打开完整播放器。音乐操作不触发手机拖拽，其他状态栏区域仍可拖动。

主页按 iOS 主屏方式整理为两页：第一页依次为相册、音乐、小红书、抖音、微博、X、论坛和通知，第二页为生图、调试和角色手机。消息、通讯录、朋友圈、设置固定在底部磨砂 Dock，不在页面里重复摆放；消息未读角标保留。统一图标的圆角、视觉尺寸、光影和轻按反馈，音乐使用白色音符与珊瑚粉图标。支持原生触屏/触控板左右滑动、鼠标横拖、页码圆点和方向键翻页，横拖不会误打开应用或移动手机；搜索覆盖全部 15 个应用。当前页与搜索文字在本次手机运行中保留。请求进度只更新提示文字，保持加载动画与按钮节点；酒馆刷新时复用主屏幕和底部 Dock，局部更新时钟、当前聊天与未读角标，避免磨砂层反复重建造成闪烁。顶部时间卡片遵循原有设备/RP 时钟设置，未知剧情时间不借用设备时间；短屏缩小图标与卡片、保留应用区滚动。

朋友圈采用简洁封面与个人资料、分段切换、轻量搜索和纵向动态时间线；保留发布、生成、点赞、评论、收藏、转发、删除、图片及正文同步入口。生成结果里若混入冒充玩家的评论，仅本地过滤对应评论，不丢弃主帖及其他有效评论，不改名冒充别人，也不追加模型请求。

「音乐」是 Selene 本体的控制界面，按[公开音乐库 v2 协议](https://github.com/soso454u/-/blob/main/MUSIC_LIBRARY_API.md)（2.10.108+）直接调用 `getCapabilities/getMusicLibrary/getQueueState/searchMusic/cancelMusicSearch/playTrack/playPlaylist/addToQueue/toggleFavorite`。首页、搜索、音乐库和待播清单共用现有 MusicIsland 的 ROOT、播放快照、事件和进度计时，不创建第二个音频或数据库；收藏、歌单及队列均由播放器保存。列表每页最多 30 条；搜索由用户显式提交，分页及收藏状态刷新复用原 `searchId`，不会重新搜索。最近播放仅展示本次打开期间实际观察到的最多 5 首歌曲快照，不伪造播放器未公开的完整历史、不持久保存。全屏页展示真实封面、歌名、歌手、进度与播放控制；封面失败显示本地 CSS 唱片样式，迷你播放器跨音乐页面保持。v1 播放器保留基础播放页；未连接只展示等待连接页面。实例更换后重新握手并丢弃旧引用；最小化、切应用或卸载取消手机搜索和多余刷新，不暂停真实音乐。

全屏页新增「封面 / 歌词」切换，按 Selene **2.10.110+** 的实际公开接口逐项检测：`getLyricsState()`、`getPlayMode()/setPlayMode(mode)`、`getPlaybackSources()/setPlaybackSource(source)` 和 `setS01SQuality(quality)`。仍由同一个 MusicIsland 桥接监听 ROOT 上的 `selene-music-lyrics-state` 与 `selene-music-playback-options-state`，原播放与音乐库事件保持不变；不另连播放器。没有某个方法只降级该项，歌词页明确显示版本不支持提示。

歌词首次打开及歌词事件变更时读取快照，按 v1 播放 `trackId`（不是 v2 音乐库 trackRef）与 `revision` 校验；切歌、实例变化或卸载立即清理旧歌词，异步旧结果不再应用。原文与翻译按组安全显示；纯音乐、无歌词、失败和限流保留播放器的实际提示。使用共享 `estimatedTime()` 二分查找活动行，仅修改当前行和相邻行状态，点击歌词通过 `seekTo(time)` 跳转；暂停保持当前行，拖动进度立即预览对应行。手动滚动时暂停自动居中，停止操作约 3.5 秒或点「回到当前歌词」恢复跟随；切回封面、收起播放页、换 App、页面隐藏或最小化后停止歌词跟随更新与定时器。本版采用逐行同步，没有按文字长度生成逐字时间。

播放控制为「播放源 / 上一首 / 播放暂停 / 下一首 / 播放模式」五键布局。左侧打开底部选择面板，来源、是否可用和 S01S 音质完全采用 `getPlaybackSources()` 的 `options/qualityOptions`，同时显示所选偏好 `selected` 与已确认实际来源 `actualSource`；不把显示名称当作 setter 的 ID。选择源或音质时锁定重复提交，成功后回读真实状态，失败显示播放器原错误并保留已确认选项。S01S 音质 setter 可能重播本曲并沿用播放器回退，实际音源可以与偏好不同。右侧按 `loop → one → shuffle → loop` 调用模式 setter，使用真实返回与回读结果显示图标；不维护另一套播放顺序。播放器本体修改模式、源、音质或 S01S 配置后，选项事件触发回读，不刷新搜索、音乐库或整个音乐 App。

聊天输入框旁的「＋ → 分享音乐」可以预览并确认发送 Selene 当前歌曲卡片。只在用户主动确认时，按原有玩家消息流程发送歌名、歌手和封面地址；不保存音频直链、临时 `trackRef` 或完整音乐库，也不重新搜索、不自动请求角色回复。角色下次正常回复可读取这条主动分享的歌曲信息，现有角色设定及音乐偏好仍按原上下文处理。

音乐联动只持有 UI 状态，不读 localStorage、不扫描 audio、不新建音频、不读播放器数据库、不自行调用音乐或 AI API；用户搜索通过播放器公开接口完成。除上述用户主动发送的歌曲卡片外，播放信息不进入账本、剧情同步、世界书、记忆或模型提示词；音乐 UI 自身零 AI Token 消耗。初始化与重新打开读取真实状态，其后靠事件更新；仅手机可见时每 4 秒检查接口引用及方法是否仍存在。音乐 App 或灵动岛卡片可见且有歌曲正在播放时，共用每 500 毫秒的进度估算；15 秒没有真实状态才补一次读取。最小化或页面隐藏停止上述定时器与音律动画；卸载只清理手机资源，不暂停音乐。


页面背景：在任意应用右上角点击调色盘，或到「设置 → 外观 → 页面背景」选择页面。页面入口使用双列色块卡片，显示名称和当前样式，可按名称搜索。聊天背景：点击顶部联系人头像，或在输入框左侧「＋ → 更多会话操作」更换当前会话背景；「默认聊天背景」可统一设置未单独指定背景的会话。支持预设配色、图片地址、本地上传、遮罩和恢复默认。背景只用于界面，本地图片保存在 IndexedDB，不发送到模型；聊天背景随当前聊天备份恢复，页面级偏好保存在账号设置。

小红书使用双列封面笔记，点击进入详情；抖音使用竖屏画面卡片，微博使用动态列表，论坛突出标题与讨论。只有实际提供图片地址时才显示图片，画面说明按描述封面呈现。搜索与「我的／收藏」使用已有记录，不自动发起生成请求。消息气泡保持原版蓝灰短尾样式，发送和其他会话操作收在输入框旁。

API 响应读取已对照 [Cache Memory 的 API 客户端](https://github.com/soso454u/SillyTavern-Cache-Memory/blob/main/src/api-client.js) 与 [Selene 播放器](https://github.com/soso454u/-/blob/main/%E7%BA%AF%E9%9F%B3%E4%B9%90%E6%92%AD%E6%94%BE%E5%99%A8.js)：沿用酒馆同源代理与 JSON 请求头，并检查实际响应内容以兼容错误或缺失的 SSE 响应头、无空行分隔的事件、JSON 回退及分段正文数组。网页响应会独立提示，不再一律推断为服务器故障。

## 双向同步与记忆

- **自动**：在下一条正常的、非空的用户正文消息中附加一份 `<phone_events>`，按字数上限分批交接。没有待同步事件时不追加、也不写临时提示。手机不会新增虚假的角色楼层或写入世界书。纯表情和纯笑声默认仅留手机，可单条改为纳入；确认的重要约定、评论、点赞等不会仅因短而丢弃。
- **手动**：在调试页点「安排下一条正文发送」；**暂停**保留原队列；**关闭**期间的新事件默认仅本地，既有队列不会被销毁。重新生成和 Swipe 不交接新事件；原先已写入真实用户消息的批次仍随所处楼层参与后续历史。手动编辑正文请保留完整数据块；可用仅影响显示的规则折叠，不要让 Prompt/摘要处理抹掉整个块。
- 账本区分**待同步**、**已写入剧情来源**、**已参与生成**、**本地记忆**和**外部归档未验证**。记录只有在监听到带该块的正文请求且得到有效回复后，才显示「已参与生成」。这不是模型承诺记住，也不是服务器写盘或 Cache Memory 归档回执。Cache Memory 可以通过自己的 `summaryUserSource()` 读取该用户楼层，但不假定它必然覆盖某事件；本脚本不写、也不伪造第三方摘要。
- 本地保留原文及编辑旧版本，按需读取最近消息、旧原文、阶段摘录和手动确认的长期事实。阶段整理只在累计达到阈值后运行，不调用模型。删除、改写、分支或 Swipe 改变时，以事件所属来源前缀与当前分支核对，未匹配的档案不会出现在当前聊天。
- **存储**：设置使用酒馆账号存储；手机原文用浏览器 IndexedDB，按账号、角色卡/群、聊天文件、有效分支隔离。交接块通过酒馆已有保存机制跟随聊天文件；不是全量跨设备同步。迁移时同时备份酒馆聊天文件与手机「导出当前聊天」的 JSON，目标设备打开同角色/群及该聊天文件后再恢复。同 ID 保留现有记录；派生 checkpoint 和本机的参与请求证据不随备份恢复。导出的 JSON 可能包含私聊，请妥善保管。

## 识别正文里的手机消息

优先使用既有 iMessage 规则或可配置的 XML/JSON 标签名。`user` 指玩家，`char` 指当前角色；多人时请写确定的人名。用逗号分隔 XML 收件人及可见人，JSON 用数组。`type` 支持 `message`、`post`、`comment`、`like`、`call`；动态的 `id` 与互动的 `target` 用于关联。未指定可见人的动态不会默认公开，正文里的不明确描述不会被补成既有事实。

```xml
<phone_event type="message" from="顾砚卿" to="user">下班了吗？我在楼下等你。</phone_event>
<phone_event type="post" id="p1" from="顾砚卿" visibleTo="user,宋悦">今天做了蛋糕。</phone_event>
<phone_event type="comment" from="宋悦" to="顾砚卿" visibleTo="user,顾砚卿" target="p1">看起来很好！</phone_event>
<chat owner="user" peer="char"><im sender="char">晚点见。</im></chat>
```

```xml
<phone_log>[{"type":"call","from":"顾砚卿","to":["user"],"text":"约在下班后见"}]</phone_log>
```

正文可写 `顾砚卿给林遥发了一条微信：“下班了吗？”`。只有当前聊天确定为一对一、且通讯录只有玩家与当前角色时，才将当前角色发给「她／他／你」的明确原话归给玩家；多人场景要写名字。反向事件只在手机显示，不再次回传到正文。需要补写未明确内容时，可手动用「角色主动」生成一条**新**消息，不会篡改原文来源。

## 上下文与隐私边界

- 手机请求以手机专用预设开头，再加入 Persona、角色卡与相关 NPC、世界书、剧情摘要和记忆、当前分支近期正文、相关手机档案、近期手机聊天，最后是本轮任务。**不读取、不继承、不修改酒馆正文预设**；只存在于正文预设、但适用于手机的人物规则，可手动补进手机专用预设。升级会丢弃旧的继承配置，把未改动的旧默认预设迁移至内置 `PHONE_PRESET`；保留用户编辑过的预设及其他手机设置。
- 「设置 → 手机专用预设」可编辑、启停、导入 UTF-8 文本、导出当前编辑文本到 `PHONE_PRESET.txt`，或恢复内置默认文本。编辑和启停需保存；导入/恢复会保存文本但不改变启用状态。`CORE` 用于连续性与行为，`CHAT` 仅用于聊天，`GROUP` 仅用于群聊，`SOCIAL` 仅用于社交任务，`OUTPUT` 只组装当前应用的协议。自定义文本可使用对应模块标题（如 `[GROUP]`）；无标题的文本视为 `CORE`。关闭行为预设仍保留 JSON 协议和已有剧情资料，不额外请求模型分析或摘要。
- 世界书优先使用当前分支的原生活化记录，同时只读匹配常驻及直接关键词条目。没有原生记录时，递归、概率、分组和计时等高级活化不会模拟。手机不运行会更改正文注入状态的酒馆世界书扫描。已激活的 iMessage / 表情库存 / 社交条目按任务只读必要部分，不注入正文美化容器或图片 URL。
- 从当前聊天读取已保存的原生摘要；Cache Memory 优先使用从正文请求中独立识别的记忆块，不能核对时只使用与当前正文指纹一致的已存摘要。不会复制整份正文请求、读取位置上未标识的扩展提示，或把未知内容猜成剧情摘要。调试页保留实际入选来源、各来源估算 Token、同步状态和告警；Token 不是供应商计费数。
- 手机账本按可见范围过滤，并在发送给其他角色时过滤能可靠识别的私密手机原话。**不等同于对任意正文、世界书或第三方摘要做逐条脱敏**；它们可能含有作者视角的信息。若不应发往外部模型，请关闭对应来源、缩小正文窗口并先预览。正文中的交接块本质上是作者视角数据，会带上知情范围；模型仍可能不遵守角色知识边界。
- 独立密钥单独持久保存到当前酒馆账号的浏览器存储（非加密密钥库），不写原文、提示词或聊天备份；仍会随请求经用户的酒馆服务器转发至指定供应商。请使用信任的酒馆实例及供应商，非本地地址用 HTTPS。脚本不替用户做服务端日志治理。停用或刷新会取消手机等待；供应商是否停止计算或计费取决于上游。

## 开发与验证

结构化 `chat/im/social` 读取原始正文；社交标签按 `platform` 分流。仅在正文明确写出平台、作者及完整原话时，也能从简单自然语言识别发布事件。普通概述（如「他发了篇笔记」）不会被编造为完整笔记；`<social platform="朋友圈/小红书/抖音/微博" name="作者显示名" time="已知时间">` 会直接识别；time 未知可省略。正文明确署名但不在通讯录的作者、评论者按平台账号保存，不冒充当前角色，也不自动加入私聊联系人。支持 s-text、s-title、s-gallery/s-image、s-video、s-tags、s-location、s-avatar、s-likes、s-repost、s-stats/s-count、s-comments/s-comment；保留已知媒体、回复关系和互动数字，未知总评论数不按展示条数推测。只有评论数字时不生成空评论记录。识别过程不调用模型、不补评论或未知资料；仅提及平台或刷手机不触发。升级后会重新识别已有正文（已清空的来源仍保持隐藏）。现有消息和朋友圈账本不清空，新增平台沿用相同事件结构及 ID 体系，备份保留媒体结构。

当前限制：语音、视频、红包等组件只展示已知事实，不生成可播放资源或执行真实资金操作；社交页面是 RP 模拟，未连接真实平台。原版正文资源严格保留，手机内部采用微信式聊天，部分特殊组件以说明卡显示。上下文预览可逐项展开并估算 Token，尚未提供逐条来源的持久化筛选面板。自动云端保存是防抖的完整聊天元数据保存，单份完整手机云端备份上限 64 MiB（含相册图片），超出时明确报错并保留原备份，不截断数据；同版本事件冲突保留副本，服务器正文不一致则拒绝覆盖，但不具备服务端原子比较交换能力。真实酒馆及第三方供应商需在实际环境验证。

Node.js 22+，无安装依赖。`npm run build` 同时生成完整脚本 `dist/Selene手机.js`、兼容入口 `dist/外置小手机.js`、同内容的远程入口 `dist/index.js`，以及可粘贴的一行加载器 `dist/import.js`。`npm test` 检查独立上下文、同分支剧情记忆、交接、反向识别、隔离和取消。`src/` 分为领域模型、IndexedDB 账本、双向同步、上下文、剧情来源、API、编排和 Shadow DOM 界面。

发布新版本：先更新 `package.json` 的 `version` 并运行构建，将源码和 `dist/` 成品提交到仓库，再为这次提交创建并推送同名版本标签（例如 `v0.1.1`）。标签所指提交必须包含 `dist/index.js`。每版使用新标签，保留旧版本，便于使用者修改 import 中的版本号来更新或回退；不要改写已发布标签。GitHub 文件通过 jsDelivr 提供的版本路径遵循[官方 GitHub 加载规则](https://github.com/jsdelivr/jsdelivr#github)。

浏览器冒烟页：在项目根目录运行 `python3 -m http.server 8765 --bind 127.0.0.1`，访问 `http://127.0.0.1:8765/test/browser.html`。它使用本地模拟的酒馆事件和响应，可验证双向同步、无增量不注入、重载后 IndexedDB 恢复、切换聊天隔离和卸载；不要将测试页当成实际供应商联通测试。酒馆实机建议先使用测试聊天：手机发送一次、正文发送两次，核对第一轮 `<phone_events>`、第二轮无新增块，再切 Swipe 并检查手机来源。

音乐最小验证页：构建后访问 `http://127.0.0.1:8765/test/music-island.html`。原「运行最小验证」保留灵动岛 v1 检查；「验证音乐 App v2」一次检查播放器缺失及 v1 降级、v2 握手、播放暂停/切歌/seek、搜索与收藏双向更新、歌单、队列、跨页迷你播放器、主动分享卡片、壁纸、热重载及卸载。使用交付脚本和公开协议模拟，不连接真实音乐/模型服务；模拟歌曲仅存在于测试页。评论过滤另有 Node 回归测试。实际播放器供应商音源与搜索联网能力需在用户运行环境确认。

### 群聊与社交网名

聊天信息中的加号打开联系人选择页：私聊默认勾选当前联系人，再选其他联系人后点击完成建群；消息页也可直接选择至少两位联系人建群。新群默认名为「群聊」，在聊天信息 → 群聊名称中修改。在已有群聊里点击加号只添加成员，不另建群。

朋友圈头像可打开自己的「社交网名」设置；点击动态作者可设置网名并绑定对应人物，私聊的聊天信息也有「社交网名」入口。设置 → 正文同步 → 网名与人物对应支持逐行编辑 `网名=人物名`。本次按已确认关系预填 `Louis=明玉`，仅当当前人物中存在明玉时匹配；不会推测未知账号。网名用于新发动态与评论，历史正文保留屏幕署名，按绑定身份使用头像、归入「我的」，原名和以前保存的网名继续可识别。修改对应关系后自动重读正文。

朋友圈媒体使用独立网格：已有图片直接显示，没有 URL 时显示可点开的画面说明卡，视频标有播放图标；不凭空补图。评论编辑器分别使用朋友圈绿色、小红书粉红、微博橙色、抖音红色、论坛蓝色和 X 蓝色，并继承页面明暗。底部返回横条跟随当前页面文字色和背景色切换。


### 请求排队与生图设置

回复、主动消息、动态、补充评论、生图和连接检查共用先入先出的请求队列；等待时可继续提交，活动提示显示排队数量。取消仅停止当前任务，清空队列仅撤销尚未执行的请求。每项保留提交时的目标会话，执行前读取最新手机消息；切换酒馆聊天、编辑正文或切换剧情分支后，失效待执行任务不发请求。失败不重试，后面的独立请求仍继续。队列只在本次页面运行中保留，刷新或卸载会撤销等待任务。

生图模型输入框右侧独立下拉选择器始终列出已读取的全部模型，不按已填内容过滤，仍可手填。外貌参考改成可增删的角色卡片，每位角色有姓名和六行起的多行提示词；兼容原来的「姓名：外貌」内容。画面规则从社交通用提示词中分离；只清理能精确识别的旧内置配图段落，保留用户自己的平台规则。图片条目仍分别使用现有 `s-image` 结构。


新动态的每张图片在 `fields.prompt` 中提供英文单张提示词，`text` 继续用于中文画面说明。点击生成图片时，直接使用已有提示词；未填提示词则直接使用画面说明。角色参考、画风、补充词及负面词按现有规则原样组装，不自动调用文本模型转换，也不因包含中文而额外请求一次 API。需要生成英文提示词时，用户主动点击 AI 按钮，使用当前默认文本 API，不跟随平台专属 API。


图片放大页底部提供「删除图片」，可移除当前显示的生成图（包括尚未存相册的生成缓存）或相册图片。删除只针对选中的本机图片记录，保留动态正文和原始画面说明。

生图设置 →「我的提示词方案」支持保存最多 30 套命名方案。填写画风、自定义画风、正向补充词与负面词后命名保存；同名保存会更新原方案。在下拉框中选择方案即切换，也可删除不用的方案。方案按当前酒馆账号持久保存，不包含 API 地址、密钥、模型、尺寸或角色外貌参考，切换时这些设置保留。


### 独立生图规则与自动保存

「画面工坊 → 生图设置」按连接与模型、画风方案、生图规则、角色参考和生成参数分组；每次重新进入时默认收起。模型旁可直接拉取列表。普通设置同样在重新进入时全部收起，不记忆上次展开状态。选择和开关立即保存；文本输入停顿约半秒或离开输入框后自动保存，并显示保存状态，无需再点总保存按钮。API 与生图提示词方案均为选择即切换；命名保存仍用于保留多套方案。

「生图规则提示词」为当前酒馆账号独立保存的全局配置，支持长文本编辑、自动保存与恢复默认；跨聊天、连接方式及画风方案保留。默认采用「IMAGE_GENERATION_RULES」十条规则，结合标签与具体视觉描述，保留主体、人物、动作、局部构图、环境材质和实际光照，画风仍由独立画风提示词控制。仍与此前两版内置规则完全一致的设置自动更新；自定义内容保留。生成动态时由文本模型将规则用于每张图片的画面理解，中文说明与英文 `fields.prompt` 描述同一画面；纯文字动态不强制配图，补评论与聊天回复不额外注入。手动点击画面工坊的 AI 按钮时复用这些规则，规则文本不会直接发送给生图模型。点击生图不自动翻译正向词、角色参考或负面词；保留后端原有负面词协议。角色参考优先匹配明确身份，再匹配描述中的完整姓名，避免子串误匹配；动态作者不自动视为出镜人物，手动画面工坊所选图片人物仍作为明确身份参考。

六个社交平台（朋友圈、小红书、抖音、微博、论坛、X）的图片统一在原帖上打开预览浮层；多图切换仍留在同一原帖，关闭后保留帖子与滚动位置，重新生图也沿用原帖内面板。


聊天「照片 / 拍摄」可先点击「AI 生成说明与提示词」，根据当前可见剧情准备中文画面说明和英文词；已有说明时按该画面重新组织英文词；主动点击 AI 按钮即表示重新生成，已有英文词也可更换，成功后采用并保存 AI 返回的新词。草稿可编辑并直接发送，不会因生成文字而自动生图；单独点击「生成图片（可选）」才请求生图并加入相册。每张照片可从当前可见的相册内容中选择，发送后保留独立的本机图片引用，刷新或删除原相册条目不会令已发照片失效。多张照片各自维护说明、提示词与所选图片。

正文或历史图片没有英文词时，可在图片预览或生图编辑器中点击 AI 补词。手动补词使用当前默认文本 API 与相同的画面理解规则，按当前聊天、图片来源与原说明独立缓存；不修改酒馆原文，原说明改变后不套用旧词，普通补词不覆盖图片自带的英文提示词；主动点击 AI 重新生成时，会采用并保存新词，原始正文仍不修改。只有用户选择生图时才调用生图模型。


帖子详情及操作菜单统一使用「正文同步」开关与可见范围说明，移除重复的同步按钮；未提供屏幕附加资料时不渲染 `null` 文本。构建产物首行包含内容指纹，两份常用入口生成后逐一回读校验；定向验证也直接运行成品中的 ImageService，防止源码已更新而交付脚本仍使用旧的自动转换逻辑。


单条帖子正文同步现在明确显示「已开启 / 已关闭」。关闭后，本帖及评论不会进入后续新增正文交接；已写入历史楼层的区块保留，界面会提示存在历史交接。开关按用户选定状态保存，不依赖旧界面的状态反转；关闭状态也按来源引用保存。补评论等异步请求返回时读取最新开关，最终组装交接内容前再核对最新关闭状态，旧待同步标记不能绕过关闭设置。

正文回读会核对紧邻上一轮交接的手机消息来源、会话、发送者、内容及明确时间。确认是原消息回显时只保留手机原消息，不重复导入；旧缓存中的对应重复项也会隐藏，不改酒馆正文或删除原消息。用户实际重复发送、新回复及无法确认来源的内容照常保留。

手机软键盘弹出时保持输入前的窗口缩放，只上移并缩短可用内容区；收起键盘后恢复原高度和位置。触屏输入框使用至少 16px 字号以避免 iOS 自动放大页面。聊天消息独立滚动，输入栏固定在底部横条上方；原来已滚动到底部时，键盘调整高度后继续显示最新消息。


聊天时间改为较小、较淡的分隔文字，减少上下留白。同一天只显示时分，跨天显示月日；跨年份时保留年份，原始完整时间保留在悬停提示及无障碍标签中，不改变记录里的 RP 时间。

数据同步与本地导出现在采用相同的完整范围：当前酒馆聊天下的所有手机私聊和群聊、六个平台的帖子/评论/互动、联系人、群设置、置顶/静音/已读/隐藏/正文同步开关、相册及已发图片的实际图片内容、补写的图片提示词、外观/表情包/预设/平台规则、生图规则/画风方案/角色参考和生成参数。不同酒馆聊天仍隔离；不是将其他聊天的记录混入当前聊天。API 地址、密钥、模型、连接方式、连接方案和平台 API 分配不写入备份，恢复时保留接收设备的连接配置。外部音乐播放器自行管理的音乐库不属于小手机账本。

开启自动云端保存后，设置、提示词、相册与平台状态的修改也会触发防抖同步；同步完成只更新设置页状态，不中断输入。每次同步回读验证服务器结果，并按上次成功同步的状态合并设置；本机未修改的字段可接收远端更新，同时修改时保留本机字段，明确点击“从云端恢复”则采用云端设置并合并记录。已删相册项带删除标记，避免合并时复活。恢复图片使用接收端隔离的资源引用。同步期间新发生的修改保留并安排下一次保存。旧版仅含事件的备份仍可导入，缺少的新字段不会清空已有相册或设置。更新后在原设备先点一次“立即同步”，其他设备打开同一个酒馆聊天后点“从云端恢复”。

### 角色手机与多 NPC 消息

主屏第二页（生图、调试旁）新增「角色手机」。进入后可在顶部选择当前角色或 NPC，显示独立手机桌面，包含聊天记录、备忘录、浏览记录和购物车。聊天从当前酒馆聊天的有效正文与手机账本读取，按手机主人展示收发方向；点击顶部返回逐级退出，底部横条返回角色桌面，桌面再退出回到自己的手机。

正文中明确出现的多 NPC 手机参与者会自动识别，无需先手动加通讯录：包括具名的 `<im sender="npc/char" name="人物名">`、`<chat owner="char" peer="npc" name="联系人">`，以及有明确收发双方的 `phone_event / phone_log`。单个多 NPC 角色卡中的具名发言人分别建立会话；`chat` 内只有一位明确具名的 `char` 时，将该姓名用于本段的 char 身份。独立 `im` 遵循原协议，视为与 user 的消息；NPC 之间的私聊须用 `chat` 明确手机主人和联系人，不从模糊旁白猜测收件人。只有给 user 的消息进入自己的消息列表，角色之间的私聊仅在相关角色手机展示。已有「网名与人物对应」同样用于聊天身份匹配，只有映射目标已存在才归并。

角色手机右上角「生成」可勾选聊天记录、备忘录、浏览记录和购物车，所有选中栏目合并在一次 API 请求中返回和保存；不逐栏调用，不自动重试或补请求。生成期间同一角色的按钮禁用，请求队列也按角色去重，重复点击不会再排一轮。默认精简生成，已有私人记录只带短摘要，减少重复上下文。重新生成只替换所选栏目的模拟记录，原始正文聊天保留。聊天可生成角色与其他 NPC 的历史会话，不生成 user 发言；模拟消息仅在角色手机查看，不实际发送或进入 user 的收件箱。购物车不代表已购买，浏览记录不访问真实网站。

生成的私人内容按角色、酒馆聊天与有效剧情分支保存，刷新后保留，随现有本地导出和云端备份一起携带。普通查看不注入剧情，也不会进入其他人的普通聊天上下文。正文编辑、删除和 Swipe 后，已不在当前有效分支的聊天及生成记录隐藏。新增范围的最小验证为 `node --test test/character-phone.test.cjs`；浏览器测试页支持模拟四类栏目，不连接真实模型。

已经生成并保存的记录可直接点击「同步剧情」，不必重新生成。勾选聊天记录、备忘录、浏览记录或购物车，预览后点击「安排下一条正文注入」；聊天详情中仅选择当前会话。所选资料完整附在下一条正常酒馆正文用户消息中，玩家可自行输入“我查看了她的手机，翻到她和朋友的聊天”等行动。勾选、预览和安排同步均不调用模型；它只提供参考资料，不替玩家行动或让所有角色自动知情。自动正文同步关闭时，主动选择的角色手机资料仍可交接；其他未选择的私人栏目不会带入。

待注入内容按聊天保存，可在发送前取消；同一选择不会重复排入，同一批已交接资料不会在后续正文再次注入。每次为这部手机重新安排时替换它未交接的选择，历史正文保留；需再次查阅时可主动重新选择。单次安排最多 24000 字符，超出需减少栏目或仅同步当前会话，不静默截断。明确选中的资料按完整编码长度预留正文交接空间，原有普通消息沿用原交接预算。
